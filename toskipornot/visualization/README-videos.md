# Robustness demonstration videos

Video loops showing how each U-Net variant's segmentation reacts as image
quality (texture disparity) is perturbed, and how the architectures differ.

## Layout

Every frame is 4 columns × 6 rows. One row per architecture; per row:

| Column | Content |
|---|---|
| 1 | Clean (unperturbed) image |
| 2 | Ground truth, overlaid on the clean image at 45% opacity (cyan) |
| 3 | The perturbed image at the current texture-disparity level |
| 4 | That model's prediction on the perturbed image (magenta fill) with the ground truth outlined in cyan, plus the per-case Dice |

Column 3 is identical down the whole column — at any instant every model is
seeing exactly the same perturbed input, so column 4 isolates the effect of
architecture alone.

The time axis walks the perturbation level and then walks back
(hardest → easiest → hardest), so each clip loops without a visible jump, and
cycles over several test cases.

## Outputs

`results/videos/`

| File | Content |
|---|---|
| `robustness_busi.mp4` | Breast ultrasound (BUSI) |
| `robustness_glas.mp4` | Colon histology (GLaS) |
| `robustness_heart.mp4` | Left atrium (Heart MRI) |
| `robustness_spleen.mp4` | Spleen (CT) |
| `robustness_synthetic_background.mp4` | Foreground texture bleeding into the background |
| `robustness_synthetic_foreground.mp4` | Background texture bleeding into the foreground |

Rendered frames are kept alongside in `frames_<name>/`, and cached predictions
plus per-case Dice in `results/video-cache/`.

## Perturbation axes

**Medical** — the five variants in `data/*-experiment/`, ordered from lowest to
highest texture disparity. Generated by
`toskipornot/analyze/generate_figure_histogram_busi.py`:

| Variant | Meaning | How |
|---|---|---|
| `lower` | Hardest | speckle noise, var 0.3 |
| `low` | Harder | speckle noise, var 0.1 |
| `in-domain` | Unperturbed | as trained |
| `high` | Easier | background blur |
| `higher` | Easiest | stronger background blur |

**Synthetic** — 15 alpha-blend levels from
`toskipornot/data/generate-textures-{background,foreground}-variation.py`.
As α → 1 the two textures converge and the task degrades:

- `background-processed`: `blend(bg, fg, α)` composited *outside* the mask, i.e.
  the foreground texture bleeds into the background.
- `foreground-processed`: `blend(fg, bg, α)` composited *inside* the mask, i.e.
  the background texture bleeds into the foreground.

All synthetic checkpoints were trained at α = 0.10 (maximum disparity), and are
evaluated on the held-out tail of each set (cases 80–99); cases 0–79 were used
for training.

## Reproducing

```bash
uv venv .venv && uv pip install -r pyproject.toml

.venv/bin/python -m toskipornot.visualization.make_robustness_video --dataset all
.venv/bin/python -m toskipornot.visualization.make_synthetic_video --scenario both
```

Useful flags: `--n-images`, `--seconds-per-frame`, `--device` (`cpu` or `mps`),
`--out-dir`. Predictions are cached, so re-rendering with different timing does
not re-run inference. Requires `ffmpeg` on PATH.

## Correctness

Inference was verified against the numbers already committed in `results/`:

- Medical: per-image Dice for BUSI (`UNet`/in-domain, `AttentionUNet`/lower,
  `UNet++`/low, all 147 cases) matches `results/BUSI-results/*.csv` to ~2e-8.
- Synthetic: `UNet` trained at α=0.10, tested across the nine published alphas,
  reproduces `results/background-results/dice_for_unet.csv` to four decimals.

One subtlety mattered: MONAI's `PILReader` swaps the first two array axes
relative to PIL, so the training and evaluation pipeline in this repo fed the
networks **transposed** images. `predict()` therefore transposes going in and
coming back out — keeping the display in natural orientation while matching the
published numbers. Without this the Dice values are systematically wrong (e.g.
BUSI `UNet`/in-domain drops from 0.748 to 0.598).

## Caveats

- **Weights provenance.** The checkpoints under `reports/` and `models/` were
  recovered from a truncated `reports.zip` by scanning zip local-file headers
  and inflating the member streams directly; the archive's central directory was
  missing. All recovered members inflated to exactly their recorded uncompressed
  size except `spleen-v4.zip`, which lost its final ~49 MB.
- **Spleen VNet** seed 1 was inside that lost tail, so the spleen video uses
  VNet **seed 2**. This is labelled in the row header of the affected frames.
- **GLaS VNet** is a degenerate checkpoint: it predicts all-foreground
  regardless of input. This is a property of the released weights, not of this
  pipeline — the committed `results/GLaS-results/GLaS_stats_VNet_*.csv` files
  are byte-identical across all five variants (mean Dice 0.7134, std 0.2083)
  for the same reason. Its row is therefore flat across the whole sweep.
- **Spleen collapses in both directions.** Every architecture scores ~0 on the
  `high`/`higher` (background-blur) variants despite in-domain Dice of
  0.81–0.97. This reproduces the committed
  `results/Spleen-results/*.csv` (e.g. published `UNet` 0.050 / 0.007), and is
  worth reading as a caution: blur raises texture disparity but is *itself* an
  unseen domain shift, so "easier" on the disparity axis is not easier for the
  model. Heart behaves the same way, less severely.
- Test cases for the medical videos are not fixed: they are chosen per dataset
  by probing candidates and keeping those with the largest drop from in-domain
  to hardest (requiring in-domain Dice ≥ 0.55), so the clips actually show the
  effect rather than cases that are trivially easy or already broken.
